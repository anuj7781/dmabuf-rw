The new commits fix the flag truncation, the work item reuse, the early file
put, and the reservation-wait ordering.  One follow-up audit remains.

The signalling annotation only covers the final percpu-ref callback:

> static void dma_buf_io_map_active_release(struct percpu_ref *ref)
> {
> 	...
> 	cookie = dma_fence_begin_signalling();
> 	...
> 		dma_fence_signal(&map->fence->base);
> 	...
> 	dma_fence_end_signalling(cookie);
> }

However, the fence is published by dma_resv_add_fence() before the active
reference is killed, and the code which eventually reaches
dma_buf_io_map_active_put() includes the NVMe completion, timeout, abort, and
reset paths.  The two recovery cases returning BLK_EH_RESET_TIMER can keep
retrying while reset or PCI recovery performs reclaim-capable work.  Please
audit those paths separately; the normal abort and terminal controller-disable
paths already force-complete requests without allocation.

The remaining `percpu_ref_kill()` window is not by itself a use-after-free:
references acquired during the mode switch are counted before the release
callback runs.  Similarly, the dedicated unmap workqueue removes the earlier
same-workqueue fence starvation cycle.  Those parts look sound after the new
commits.
