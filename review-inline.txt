nvme-pci: add SGL support for the dmabuf path

This commit adds SGL support for DMA-BUF-backed NVMe requests and uses a
single fill loop for both inline and pooled descriptors.

Could this retain a check that limits entries to NVME_MAX_SEGS before this
allocation?  The block layer still reports a DMA-BUF bio as one segment in
bio_split_io_at(), so a fragmented request can produce entries greater than
the one-page descriptor capacity.  With 257 mapped entries, the fill loop
writes sg_list[256] past the 4096-byte pool object before the equality check
can reject it.

Could the request avoid nvme_pci_dmabuf_sgl_nents() when the payload is
already below sgl_threshold, or use an indexed request-relative lookup?
That helper always starts at map->sgt->sgl and consumes bi_offset.  A 4 KiB
request near the end of a 1 GiB page-granular mapping therefore scans about
262,000 entries and then selects the PRP path with the default 32 KiB
threshold; sequential small I/O makes this repeated prefix scan quadratic.
